# SQL 演習ファイル

## 目的

- `000_check_connection.sql`: 接続先データベース・ユーザー、SQL 実行可否、DB サーバー時刻を読み取り専用で確認します。
- `010_setup_sample_products.sql`: 演習用 `products` テーブルとサンプルデータを準備し、登録内容を表示します。

## 実行方法と対象

Neon Console の SQL Editor で、以下の順序で手動実行します。

1. `000_check_connection.sql`
2. `010_setup_sample_products.sql`（接続先を確認し、既存テーブルの内容が教材と一致すると確認できた後）

対象は授業で接続確認に使用した Neon ブランチおよび PostgreSQL データベースです。Preview と Production が同一 DB を参照する教材設定を前提にします。

SQL ファイルを GitHub に保存しただけでは SQL は実行されず、Neon のデータベースにも変更は加わりません。

## AI 会話アプリ V2

`ai/040_create_ai_v2_tables.sql`はV2専用の`ai_v2_conversations`と`ai_v2_turns`だけを対象にします。AI V1やTODOテーブルは変更しません。使い捨てPostgreSQL 16では新規作成・再実行と、同名の不一致indexおよび`NOT VALID` CHECK制約で停止することを確認しています。これはNeon上での実行記録ではありません。

利用者から、ローカルの`/ai/v2/`で画面、会話作成、Gemini回答、過去の会話を踏まえた追加質問、会話間分離、再読み込み後の再開が成功し、Neonへの保存も確認したとの報告があります。対象はNeon Branch `production` / Database `neondb`で、DDL適用と定義照合も成功との報告です。以下の実行記録は利用者報告であり、CodexはNeonへ接続・再照合していません。

### Neon確認・適用手順（利用者実施）

1. Neon Consoleで正確なProject・branch・databaseを確認し、試験記録に対象名と確認日時を記録します。接続文字列や認証情報は資料へ記載しません。
2. `ai/040_create_ai_v2_tables.sql`冒頭の読み取り専用SELECTを個別に実行し、`information_schema.columns`、`pg_get_constraintdef`、`pg_index`、`pg_get_indexdef`、`pg_get_expr`等の結果を確認します。既存の同名テーブル・制約・indexが期待定義と不一致なら停止し、既存オブジェクトを削除・変更して合わせないでください。
3. 適用状態が確認できない場合は、同名オブジェクトのcatalog照合なしにDDL全体を再実行しないでください。差分レビューと承認後、必要な場合だけNeon SQL EditorでDDLを実行し、結果と対象を記録します。
4. 適用後、V2画面から会話とturnを作成し、Neon SQL Editorで読み取り専用SELECTを実行して、該当conversationのtitleとturnのprompt/responseが保存されていることを確認します。ブラウザを再読み込みし、同じ会話を選んで履歴が再表示されることも確認します。
5. ブラウザ開発者ツールのNetworkで、一覧GET `200`、会話作成POST `201`、turn履歴GET `200`、質問POST `201`を確認します。確認できないstatusは推測せず未確認と記録します。
