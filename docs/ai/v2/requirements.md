# AI会話アプリ V2 要件定義書

## 1. 目的と範囲

V2は、話題別の会話作成・切り替え、会話内の文脈を使う追加質問、再読み込み後の会話選択・再開を実現する。Express/TypeScript/Neon/Geminiの既存構成を使い、AI V1とTODO V1/V2を維持する。

### スコープ

- 対象: 会話作成、会話一覧、会話切替、会話ターン閲覧、追加質問、直近会話文脈、DB保存、ローカル専用のAPI利用。
- 対象外: 認証、ユーザー別アクセス制御、会話名変更、会話削除、V1ログの移行、共有/公開会話、ストリーミング、Markdown表示。
- 運用上の前提: V2に認証はないため、V2 APIは`VERCEL_ENV`が設定されるPreview/Production等で常に停止する。静的ページが表示されてもAPI利用可能とは限らない。

## 3. 要件と受入条件

各条件は自動テストまたはブラウザー操作で判定する。`REQ-V2-*`を設計・TASK・テストで同じIDとして参照する。

### REQ-V2-001 会話の新規作成

- 利用者は会話名を入力して新規会話を作成できる。
- サーバーはtrim後の名前が1〜50 Unicodeコードポイントであることを検証し、検証済み名称を保存する。
- 成功時はHTTP 201とDB採番ID、名称、作成/更新日時を返す。DB保存前に成功を返さない。
- 受入: 有効な名称で201と保存済みDTOを得る。前後空白は保存前に除かれる。空、空白、51コードポイント、非文字列は400でDB未呼出し。

### REQ-V2-002 会話一覧・選択・再開

- `GET /api/ai/v2/conversations`は保存済み会話を更新日時降順、同日時はID降順で返す。
- 利用者は一覧から会話を選択でき、再読み込み後も同じ一覧から保存済み会話を選び直せる。
- 選択会話の履歴ロードが完了するまで空履歴として表示してはならない。
- 受入: 作成した2会話を選択すると、それぞれの履歴だけが表示される。画面をリロードし、一覧から既存会話を選ぶと保存済み履歴が表示され追加質問を送れる。

### REQ-V2-003 会話履歴の保存・表示

- 1ターンは利用者の質問とAI回答の組として同一会話に保存する。
- API/画面は選択会話の最新20ターンを古い順（同日時はID昇順）で返し、表示する。
- 20件を超える場合も最新20ターンに限定する。
- 受入: 21件以上保存したfixtureで返却件数20、並びが古い→新しいで、先頭が最新20件中最古となる。

### REQ-V2-004 会話文脈を用いた追加質問

- AI Serviceは対象会話に属する保存済み最新5ターンだけを取得し、古いターンから順にGeminiへ渡す。
- 今回のtrim済み質問を末尾に一度追加する。他会話、V1履歴、6ターン以前の文脈は渡さない。
- 受入: 6ターン以上ある会話のService境界mockで、同一会話の最新5質問/回答と今回質問だけがcontentsに含まれ、順序が確認できる。別会話/V1のfixture文言は含まれない。

### REQ-V2-005 入力・HTTP本文検証

- 会話名: 文字列必須、trim後1〜50 Unicodeコードポイント。
- 質問: 文字列必須、trim後1〜2,000 Unicodeコードポイント。
- コードポイント数はサーバーで`Array.from(trimmed).length`相当で判定する。
- JSON本文上限は16,384 bytes。入力APIはJSON Content-Typeを要求する。
- 受入: 境界長50/51、2,000/2,001、補助平面Unicode文字、空白のみ、不正JSON、16KiB超過、非JSONの各fixtureで所定のHTTP応答になり、Gemini/DBは不正入力時に呼ばれない。

### REQ-V2-006 回答生成・保存・失敗時の整合性

- 質問送信順は入力検証→会話存在確認→直近文脈取得→Gemini→空回答検証→DBトランザクションでターン保存/会話更新→201。
- Geminiの失敗/空回答時はDBを書き込まない。保存が失敗したとき201を返さない。
- 利用者は送信中に同一画面から重複送信できない。失敗時は質問入力を保持し、自動再送しない。
- 受入: deferred promiseでDB保存完了前の応答が返らないこと、AI失敗でINSERT 0回、DB失敗で503または固定DBエラーかつ201以外、UI入力保持・再送0回を確認する。

### REQ-V2-007 会話操作UI

- V2画面に新規会話名入力、作成、会話一覧、選択中会話名、ターン履歴、質問入力、送信中/エラー表示を備える。
- 非同期状態（初期取得、未選択、履歴取得、送信中、空履歴、失敗）を区別し、操作が復帰可能。
- 受入: Playwright route mockで作成、選択切替、リロード後選択、空履歴、ローディング、API障害、送信中/失敗時入力保持を確認する。

### REQ-V2-008 V2専用データ分離と永続化

- V2会話とターンはV2専用テーブルに保存し、V1の`ai_qa_logs`およびTODOテーブルを変更しない。
- V2 Modelは既存`requirePool()`を共有する。
- ターン保存は質問/回答をひとまとまりにし、会話更新と同一トランザクションで確定する。
- 受入: ModelテストでSQL/バインド値/トランザクションcommit/rollbackを検証する。実DB確認は承認・適用済みDDLを使う別試験とし、自動mock合格と区別する。

### REQ-V2-009 XSS・情報漏えい防止

- 質問、回答、会話名はブラウザでプレーンテキストとして描画し、`innerHTML`で挿入しない。
- Gemini API key、DATABASE_URL、SQL、例外本文をブラウザーや利用者向けエラーに含めない。
- 受入: script/HTML風fixtureが要素として実行されないこと、API/HTML/JS配信に秘密値が含まれないこと、内部例外が固定エラーへ変換されることを確認する。

### REQ-V2-010 V2公開停止と既存機能互換

- V2 APIは`VERCEL_ENV`が存在する環境では、設定フラグの値にかかわらず503 `DEMO_DISABLED`を返し、Gemini/DB処理を呼ばない。
- Vercel以外のローカルでは`AI_V2_DEMO_ENABLED=true`の場合だけAPIを有効にする。未設定/falseは503。
- TOP、TODO V1/V2、AI V1のルート・API契約・テーブルを変更しない。
- 受入: `VERCEL_ENV=preview`と`production`、フラグtrue/falseの全組合せで停止と呼出し0回を確認する。既存serverテスト・AI V1テストが成功し、TODO API/テストも回帰成功する。

### REQ-V2-011 固定エラー契約

- APIは既知エラーを固定文で返す。少なくとも入力400、invalid JSON 400、本文超過413、非JSON415、会話なし404、AI失敗502、DB失敗503、機能停止503、予期しない例外500を区別する。
- 受入: 各エラーのstatus/codeをSupertestで確認し、レスポンスに例外/SQL/接続情報がないことを確認する。

## 4. 未決・運用上の前提

- 認証がないため、ローカルDBに接続できる利用者は会話一覧へアクセスできる。V2 APIを公開環境で停止することを前提とし、公開運用する場合は認証・認可・ユーザーごとのデータ分離を別要件にする。
- 会話/ターンの保存期間、最大会話数、一覧のページネーション、バックアップ、削除手順、利用料金上限は未指定。TASK-V2-01で確認し、未決のままデータ削除や期限を推測実装しない。
- V2用DB DDLのNeon適用・既存オブジェクト照合・実Gemini結合試験は文書作成時点では未実施。
