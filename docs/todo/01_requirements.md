# TODO アプリ V1 要件定義

## 共通仕様

- 画面 URL: `/todo`
- API ベース URL: `/api/v1/todos`
- DB: Neon PostgreSQL。Preview と Production は同じ DB を参照する。
- タイトルは前後の空白を除去し、1～100文字とする。空白のみ・101文字以上は 422。
- ID は 1 以上の整数。形式不正は 400、形式は正しいが該当データがなければ 404。
- TODO が0件の一覧は空配列で返す。
- 認証は実装しない。個人情報は扱わない。
- タイトル変更、優先度、絞り込みは V1 対象外。
- API の成功形式は `{ "status": "success", "data": ... }`。エラー形式は `{ "status": "error", "code": ..., "message": ..., "details": [] }`。

## REQ-01 TODO一覧

- **目的:** 登録済み TODO を確認する。
- **ユーザー操作:** `/todo` を開く、または一覧を再読み込みする。
- **入力:** なし。
- **正常時:** `GET /api/v1/todos` が 200 と ID 昇順の配列を返す。0件なら `data: []`。画面にタイトル、完了状態を表示する。
- **異常時:** DB 利用不可は 503 `DB_UNAVAILABLE`。予期しないエラーは 500 `INTERNAL_ERROR`。
- **入力制約:** なし。
- **受け入れ条件:** DB の `snake_case` を API の `camelCase` に変換し、0件を正常に表示する。
- **確認方法:** 0件・登録済み状態の GET/API と `/todo` の表示を確認する。

## REQ-02 TODO登録

- **目的:** 新しい TODO を登録する。
- **ユーザー操作:** タイトルを入力して登録ボタンを押す。
- **入力:** JSON `{ "title": string }`。
- **正常時:** `POST /api/v1/todos` が 201 と作成 TODO を返し、画面の一覧が更新される。
- **異常時:** 欠落・型違いは 400 `BAD_REQUEST`、空白のみ・101文字以上は 422 `VALIDATION_ERROR`、DB 利用不可は 503、予期しないエラーは 500。
- **入力制約:** タイトルを trim した後に1～100文字。
- **受け入れ条件:** trim 済みタイトルで保存し、DB の ID・完了状態・作成日時を返す。
- **確認方法:** 正常登録と欠落・型違い・空白・101文字の API テストを行う。

## REQ-03 完了状態の部分更新

- **目的:** TODO の完了状態だけを切り替える。
- **ユーザー操作:** TODO の完了チェックを切り替える。
- **入力:** `PATCH /api/v1/todos/:id`、JSON `{ "isCompleted": boolean }`。
- **正常時:** 200 と更新後 TODO を返し、画面一覧を更新する。
- **異常時:** ID 形式不正・body 欠落/型違いは 400、存在しない ID は 404 `NOT_FOUND`、DB 利用不可は 503、予期しないエラーは 500。
- **入力制約:** ID は1以上の整数、`isCompleted` は boolean。
- **受け入れ条件:** 指定 ID の完了状態だけが変更される。
- **確認方法:** true/false の PATCH、ID エラー、存在しない ID を API テストする。

## REQ-04 TODO削除

- **目的:** 不要な TODO を削除する。
- **ユーザー操作:** TODO の削除ボタンを押す。
- **入力:** `DELETE /api/v1/todos/:id`。
- **正常時:** 204、レスポンス本文なし。画面一覧を更新する。
- **異常時:** ID 形式不正は 400、存在しない ID は 404、DB 利用不可は 503、予期しないエラーは 500。
- **入力制約:** ID は1以上の整数。
- **受け入れ条件:** 指定 ID のみを削除し、204 に本文を含めない。
- **確認方法:** 自動テストで削除対象を自分のテストデータに限定し、204本文なしと不存在時404を確認する。
